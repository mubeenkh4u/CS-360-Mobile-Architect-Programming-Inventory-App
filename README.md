# Auwire

Auwire is a **local-first ledger + inventory data platform**. The Khata remains a flexible GUI-driven table, while inventory is a strongly governed business domain that posts into that ledger atomically.

The original SNHU submission remains untouched under `Project-Files/`.

## Current capabilities

### Khata / data workbench

- Dynamic runtime columns and typed cells
- Wide, horizontally scrollable ledger grid
- Paged row loading, search and typed sorting
- DRAFT and FINAL row lifecycle for incomplete work
- Revisioned, audited editing of manual/imported rows
- System-locking for inventory-generated accounting rows
- GUI cleaning and pivot operations
- Final-only pivot analytics so drafts do not affect official totals
- Extensible custom columns without Room schema changes
- CSV import/export through Android's Storage Access Framework

### Inventory

- Product master with SKU, unit and reorder level
- Default sale and purchase rates
- Immutable committed stock movement journal
- Base/on-hand stock derived from committed movements
- Manual stock-in and stock-out adjustments
- Sale and purchase documents
- Tentative sale reservations and tentative purchase incoming stock
- Available-to-promise and projected quantities
- Tentative document commit/cancel workflow
- Stock shortage validation before committing a sale
- Atomic inventory + Khata posting
- Immediate-payment posting alongside sales/purchases
- CSV product/base-stock import and stock snapshot export

### Interface

- Auwire branding
- Separate Khata and Inventory tabs
- Collapsible left navigation drawer for each tab
- Persistent System, Light and Dark appearance modes
- File import/export without broad storage permission

## Editable rows

Manual data is no longer forced to be complete at creation time:

```
DRAFT → edit/review → FINAL
          ↑          │
          └── edit ──┘
```

A draft can be incomplete. Finalization validates required fields and typed values. Every successful edit increases the row revision and is audited.

Rows generated by committed inventory documents are marked **LOCKED**. They cannot be edited directly in the generic Khata grid because doing so could change accounting without the corresponding stock movement.

## CSV transfer

CSV is treated as an **interchange/staging format**, not as a database backup.

Khata imports:
- match existing column names case-insensitively;
- create unknown columns as TEXT fields;
- import every non-empty row as DRAFT for review.

Inventory imports:
- require SKU, Name and Unit;
- create only new SKUs;
- optionally journal Base Stock as opening stock;
- skip existing SKUs instead of silently overwriting live inventory;
- do not import reserved/projected quantities because those belong to tentative stock documents.

Android's Storage Access Framework is used for file selection, so Auwire does not request broad external-storage access.

## Stock states

For each product:

```
Base / On Hand
    = sum(committed stock movements)

Reserved Outgoing
    = quantities in tentative SALE documents

Tentative Incoming
    = quantities in tentative PURCHASE documents

Available To Promise
    = Base - Reserved Outgoing

Projected
    = Available To Promise + Tentative Incoming
```

Tentative transactions do not alter physical stock or post official Khata entries. Committing a stock document creates stock movements and ledger rows in one Room transaction.

## Financial and quantity precision

Source-of-truth business values use fixed-point integers:

- Quantity: 1 unit = 1,000,000 micros
- Money: 1 PKR = 100 paisa

## Security and integrity

- No INTERNET permission
- No broad storage permission
- App-private database
- Android backup disabled
- Cleartext traffic disabled
- Screenshot/screen-recording protection enabled by default
- Room transactions for multi-record business commits
- Explicit non-destructive migrations
- Optimistic row revisions for safe editing
- HMAC-SHA-256 chained audit events with Android Keystore key
- Audit hashes include canonical before/after row material without duplicating raw row data in the audit table
- No hard-coded production secrets
- Feature flags for independently disabling capabilities
