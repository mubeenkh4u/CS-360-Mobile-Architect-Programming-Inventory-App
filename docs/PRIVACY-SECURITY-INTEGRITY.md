# Privacy, Security and Integrity

## Privacy

The application is local-first and has no network permission. The database resides in app-private internal storage. Backup is disabled until an encrypted, user-controlled backup format is implemented.

## Integrity

Room transactions protect multi-step mutations from partial writes. Database upgrades must use explicit migrations; destructive migration is not permitted.

Audit events are append-only at the application layer and chained using HMAC-SHA-256. The signing key is generated by Android Keystore and is not stored in source code or database rows.

## Security boundaries

The Android sandbox and device encryption are the first storage boundary. Screenshot protection is enabled by default for financial data. The application does not store a home-grown password database.

Future authentication should use Android Credential Manager and/or biometric/device credentials rather than custom password cryptography.

## Data cleaning safety

Cleaning operates only on a selected column and runs transactionally. Protected accounting columns can be displayed and analyzed normally; schema-destructive operations on them are reserved for a future privileged migration workflow.

Pivots and aggregations are read-only derived results.
