# Privacy, Security and Integrity

## Privacy

The application is local-first and has no network permission. The database resides in app-private internal storage. Android backup remains disabled until an encrypted, user-controlled backup format is implemented.

## Financial integrity

Stock quantity and money are integer-backed fixed-point values in the source-of-truth inventory domain.

Physical stock is journal-derived. The application does not maintain a second mutable stock count that could drift away from movement history.

## Transaction integrity

Room transactions protect multi-step business commits. Stock movements, generated Khata rows, document state changes and audit events are committed together.

Database upgrades use explicit migrations. Destructive migration is not enabled.

## Editing integrity

User-managed rows use optimistic revisions. A stale editor cannot overwrite a newer revision.

Drafts permit incomplete work. Finalization validates required and typed values.

Committed inventory-generated ledger rows are system-locked. A generic table edit therefore cannot change accounting while leaving the corresponding stock movement untouched.

Column cleaning operations also exclude locked rows.

## Analytical integrity

Draft rows remain visible for workflow purposes but are excluded from pivot aggregation until finalized.

## Audit integrity

Audit events are chained using HMAC-SHA-256. The signing key is generated by Android Keystore and is not stored in source code or database rows.

Manual row mutation audit material includes canonical before/after cell contents, but AuditWriter persists only the SHA-256 payload hash, avoiding a second plaintext copy of the business row.

## File access

Import/export uses Android's Storage Access Framework and user-selected documents. Auwire does not request broad external-storage permission.

CSV imports are treated as untrusted interchange data:
- Khata rows enter as DRAFT.
- Finalization performs required/type validation.
- Inventory import does not overwrite an existing SKU.
- Opening stock is journaled through the normal adjustment path.
- Tentative/reserved/projected stock is not reconstructed from CSV.

## Security boundaries

The Android sandbox and device encryption are the primary storage boundary. Screenshot protection is enabled by default for financial data.

The application does not implement a home-grown password database. Future authentication should use Android Credential Manager and/or device/biometric credentials.
