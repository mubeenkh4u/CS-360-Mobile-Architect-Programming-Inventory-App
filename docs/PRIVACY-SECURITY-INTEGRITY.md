# Privacy, Security and Integrity

## Privacy

The application is local-first and has no network permission. The database resides in app-private internal storage. Android backup remains disabled until an encrypted, user-controlled backup format is implemented.

## Financial integrity

Stock quantity and money are integer-backed fixed-point values in the source-of-truth inventory domain. Binary floating point is not used for committed quantities, rates, totals or payments.

Physical stock is journal-derived. The application does not maintain a second mutable stock count that could drift away from movement history.

## Transaction integrity

Room transactions protect multi-step business commits. Stock movements, generated Khata rows, document state changes and audit events are committed together.

Database upgrades use explicit migrations. Destructive migration is not enabled.

## Audit integrity

Audit events are append-only at the application layer and chained using HMAC-SHA-256. The signing key is generated by Android Keystore and is not stored in source code or database rows.

## Security boundaries

The Android sandbox and device encryption are the primary storage boundary. Screenshot protection is enabled by default for financial data.

The application does not implement a home-grown password database. Future authentication should use Android Credential Manager and/or device/biometric credentials.

## Data cleaning safety

Cleaning operates transactionally on eligible workbench columns. Protected semantic accounting columns cannot be cleaned in-place through the cleaning UI.

Pivots and aggregations are read-only derived results and never rewrite source stock or ledger records.
